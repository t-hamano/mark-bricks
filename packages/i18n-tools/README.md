# @mark-bricks/i18n-tools

> [!NOTE]
> This is a private package. `@mark-bricks/i18n-tools` is not published to npm. It lives in this monorepo and is consumed by the hosts.

Shared i18n build tooling for MarkBricks packages. It provides the `mb-i18n` CLI that runs the gettext PO/JSON pipeline: translatable strings are extracted from source into a `.pot` template, synced into per-locale `.po` files for translators, and compiled into the Jed-format `.json` dictionaries that `@wordpress/i18n` loads at runtime.

## Pipeline

Translatable strings flow from source to bundled dictionary:

```
__() calls in source  ──make-pot──▶  <slug>.pot
                                          │
                                       make-po
                                          ▼
                              <slug>-<locale>.po  ◀── translators fill in msgstr
                                          │
                  gutenberg-<ver>-<locale>.json   (optional dependency catalog)
                                          │   \
                                          ▼    ▼
                                      make-json (merges both)
                                          ▼
                            <slug>-<locale>.json  ──▶ loaded by @wordpress/i18n
```

All files live in the consuming package's `languages/` directory:

| File                            | Role                                                               | Generated by      | Tracked?                             |
| ------------------------------- | ------------------------------------------------------------------ | ----------------- | ------------------------------------ |
| `<slug>.pot`                    | Translation template — the source of truth for which strings exist | `make-pot`        | yes                                  |
| `<slug>-<locale>.po`            | Per-locale translation source, edited by humans                    | `make-po`         | yes                                  |
| `gutenberg-<ver>-<locale>.json` | Pinned Gutenberg (`default` domain) dependency strings             | host fetch script | yes                                  |
| `<slug>-<locale>.json`          | Jed-format runtime dictionary consumed by `@wordpress/i18n`        | `make-json`       | no (gitignored, built at build time) |

## Usage

Each consuming package wires the three commands as npm scripts in its own `package.json`:

```json
{
	"scripts": {
		"i18n:make-pot": "mb-i18n make-pot",
		"i18n:make-po": "mb-i18n make-po",
		"i18n:make-json": "mb-i18n make-json"
	}
}
```

Then run them in order after changing translatable strings:

```sh
# 1. Extract .pot after source changes
pnpm --filter <package> i18n:make-pot
# 2. Sync .po against the .pot → translate the msgstr fields in <slug>-<locale>.po
pnpm --filter <package> i18n:make-po
# 3. Build the .json dictionary
pnpm --filter <package> i18n:make-json
```

Each command runs in the current package directory, so each host owns its own `languages/` dir and dictionaries.

## Commands

```
mb-i18n make-pot
mb-i18n make-po   [locale]
mb-i18n make-json
```

### `make-pot`

Extracts `__()`-family calls from `src/**` into `languages/mark-bricks.pot`, by wrapping the [`@wp-blocks/make-pot`](https://www.npmjs.com/package/@wp-blocks/make-pot) CLI.

### `make-po`

Merges `languages/<slug>.pot` into `languages/<slug>-<locale>.po` (locale is the positional argument, default `ja`), creating the `.po` when missing. The POT decides which entries exist: non-empty translations and translator comments are kept, stale entries dropped, and entries sorted on write.

### `make-json`

Compiles every `languages/<slug>-<locale>.po` into its Jed-format `languages/<slug>-<locale>.json`, one per locale, writing only translated entries. Locales come from the `.po` files on disk (no locale argument), so a new `.po` builds on the next run.

Any sibling `gutenberg*-<locale>.json` is merged in, layering its `default` Gutenberg domain on top: a host shipping the block editor commits one to translate its dependency strings, while an app-only host has none and gets just the app domain.

### Gutenberg dependency catalog

The `gutenberg-<version>-<locale>.json` that `make-json` merges is produced out of band by a host script (the editor's `i18n:fetch-gutenberg`): it downloads a pinned Gutenberg language pack from WordPress.org and unions its `.po` (PHP strings) with the per-handle JSON shards (block-editor JS strings) into the `default` domain. Re-run it only when bumping the bundled Gutenberg version; everyday `make-json` just merges the committed cache.

## Adding a new locale

Locales are identified by their WordPress locale slug (e.g. `ja`, `pt_BR`, `de_DE`, `zh_CN` — see the [WordPress locale list](https://translate.wordpress.org/locale/)). Use the same slug everywhere below: it names the `.po`/`.json` files, selects the Gutenberg language pack, and is the `code` the editor resolves at runtime.

The steps below use `pt_BR` as an example.

### 1. Register the locale in the editor

Add an entry to `LOCALES` in [`packages/editor/src/i18n.ts`](../editor/src/i18n.ts). `applyLocale` only accepts codes listed here, and the desktop app's language setting lists these entries as its options.

```ts
{
	code: 'pt_BR',
	name: 'Português do Brasil',
	matches: ( tag: string ) => tag.startsWith( 'pt-br' ),
},
```

### 2. Fetch the Gutenberg catalog

The editor ships the block editor, so it also needs the `default` domain strings for the new locale:

```sh
pnpm --filter @mark-bricks/editor i18n:fetch-gutenberg -- pt_BR --version=<version>
```

Pin the same Gutenberg version as the existing `gutenberg-<version>-*.json` files. Omitting `--version` fetches the latest version with a translation set for that locale. Commit the resulting `gutenberg-<version>-pt_BR.json`.

### 3. Create and translate the `.po` in each host

Run this in every package that has its own `languages/` directory. Make sure the `.pot` is current, then create an empty `.po` from it:

```sh
# Editor (packages/editor)
pnpm --filter @mark-bricks/editor i18n:make-pot
pnpm --filter @mark-bricks/editor i18n:make-po -- pt_BR

# Desktop app (apps/tauri)
pnpm --filter mark-bricks-desktop i18n:make-pot
pnpm --filter mark-bricks-desktop i18n:make-po -- pt_BR
```

Fill in the `msgstr` fields of each package's `languages/mark-bricks-pt_BR.po` and commit them. Keep placeholders such as `%s` intact, and read the translator comment (the `#` line above an entry, e.g. `# %s: tab title.`) for what they stand for. Leaving an entry empty is allowed: it falls back to the English msgid.

### 4. Build and check

```sh
pnpm i18n:make-json
```

`make-json` takes no locale: it compiles every `.po` it finds, including the new one, and each host picks up the resulting JSON automatically (`import.meta.glob` over `languages/mark-bricks-*.json`), so no loader code needs editing. The JSON is gitignored and rebuilt on `pnpm install`.

Then run the host and switch to the new language (the desktop app's language setting, or the OS / browser language for automatic detection) to check the UI.
