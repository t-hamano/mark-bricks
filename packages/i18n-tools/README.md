# @mark-bricks/i18n-tools

Shared i18n build tooling for MarkBricks packages. It provides the `mb-i18n` CLI that runs the gettext PO/JSON pipeline: translatable strings are extracted from source into a `.pot` template, synced into per-locale `.po` files for translators, and compiled into the Jed-format `.json` dictionaries that `@wordpress/i18n` loads at runtime.

> [!NOTE]
> This is a private package. `@mark-bricks/i18n-tools` is not published to npm. It lives in this monorepo and is consumed by the hosts (`@mark-bricks/editor`, the Tauri app, ...) via pnpm's `workspace:` protocol.

## Pipeline

Translatable strings flow from source to bundled dictionary:

```
__() calls in source  ──make-pot──▶  <slug>.pot
                                          │
                                       make-po
                                          ▼
                              <slug>-<locale>.po  ◀── translators fill in msgstr
                                          │
                  gutenberg-<ver>-<locale>.json   (optional dependency catalog)
                                          │   \
                                          ▼    ▼
                                      make-json (merges both)
                                          ▼
                            <slug>-<locale>.json  ──▶ loaded by @wordpress/i18n
```

All files live in the consuming package's `languages/` directory:

| File                            | Role                                                               | Generated by      | Tracked?                             |
| ------------------------------- | ------------------------------------------------------------------ | ----------------- | ------------------------------------ |
| `<slug>.pot`                    | Translation template — the source of truth for which strings exist | `make-pot`        | yes                                  |
| `<slug>-<locale>.po`            | Per-locale translation source, edited by humans                    | `make-po`         | yes                                  |
| `gutenberg-<ver>-<locale>.json` | Pinned Gutenberg (`default` domain) dependency strings             | host fetch script | yes                                  |
| `<slug>-<locale>.json`          | Jed-format runtime dictionary consumed by `@wordpress/i18n`        | `make-json`       | no (gitignored, built at build time) |

## Usage

Each consuming package wires the three commands as npm scripts in its own `package.json`:

```json
{
	"scripts": {
		"i18n:make-pot": "mb-i18n make-pot",
		"i18n:make-po": "mb-i18n make-po",
		"i18n:make-json": "mb-i18n make-json"
	}
}
```

Then run them in order after changing translatable strings:

```sh
pnpm --filter <package> i18n:make-pot   # 1. Extract .pot after source changes
pnpm --filter <package> i18n:make-po    # 2. Sync .po against the .pot
#    → translate the msgstr fields in <slug>-<locale>.po
pnpm --filter <package> i18n:make-json  # 3. Build the .json dictionary
```

The commands run relative to the package's own directory (`root` defaults to the current working directory), so each host owns its own `languages/` dir and dictionaries.

## Commands

```
mb-i18n make-pot  [--slug=<slug>] [--root=<dir>] [--include=<glob>]
mb-i18n make-po   [locale] [--slug=<slug>] [--root=<dir>]
mb-i18n make-json [--slug=<slug>] [--root=<dir>]
```

Defaults: `locale=ja`, `slug=mark-bricks`, `root=cwd`, `include=src/**`.

### `make-pot`

Extracts `__()`-family calls from the source files matched by `--include` into `languages/<slug>.pot`, by wrapping the [`@wp-blocks/make-pot`](https://www.npmjs.com/package/@wp-blocks/make-pot) CLI.

-   `--include=<glob>` — sources to scan. Default: `src/**`.
-   `--slug=<slug>` — text domain / file slug. Default: `mark-bricks`.
-   `--root=<dir>` — package root that owns the `languages/` dir. Default: cwd.

### `make-po`

Merges `languages/<slug>.pot` into `languages/<slug>-<locale>.po`, creating the `.po` when missing. The POT is the source of truth for which entries exist: existing non-empty translations (and translator comments) are preserved, entries no longer in the POT are dropped, and entries are sorted on write. Reports `kept` / `new` / `dropped` counts.

### `make-json`

Compiles **every** `languages/<slug>-<locale>.po` into its Jed-format `languages/<slug>-<locale>.json` consumed by `@wordpress/i18n` — one output per locale. Locales are discovered from the `.po` files on disk, so there is no locale argument; dropping in a new `.po` is enough for the next run to build it. Only translated entries are written.

Any sibling file named `gutenberg*-<locale>.json` is merged in too: its domains (the `default` Gutenberg domain) are layered into the output. A standalone host that ships the WordPress block editor commits one so its dependency strings are translated; a host that only translates its own app strings simply has none, and `make-json` writes just the app domain. The merge reads local files only — `make-json` never touches the network, so it is safe to run on every build and in CI.

The output is **gitignored**, so concurrent translation PRs never collide on the generated dictionary — they touch only the `.po`. It is regenerated by the workspace's root `postinstall` (so a fresh clone and CI have it after `pnpm install`) and can be rebuilt by hand with `pnpm i18n:make-json` after editing a `.po`. Because it is gitignored and the bundler re-minifies it on `import`, its on-disk format is read by neither humans nor git, so it is written minified.

### Gutenberg dependency catalog

The `gutenberg-<version>-<locale>.json` file `make-json` merges is produced out of band by a host script (the editor's `i18n:fetch-gutenberg`), which downloads a pinned Gutenberg version's language pack from WordPress.org, unions its `.po` (PHP strings) with its per-handle JSON shards (block-editor JS strings) into the `default` domain, and writes the committed cache. Re-run it only when bumping the bundled Gutenberg version; everyday `make-json` runs just merge the committed file.

The cache is committed but minified: it is never hand-edited, and a version bump replaces it wholesale (under a new filename), so a readable diff would buy nothing. Its keys are sorted so re-fetching the same version stays byte-stable.

## Adding a new locale

Pass a WordPress locale slug (e.g. `ja`, `pt_BR`, `de_DE`, `zh_CN` — see the [WordPress locale list](https://translate.wordpress.org/locale/)) as the positional argument to `make-po`; it defaults to `ja`. `make-json` takes no locale — it builds every `.po` it finds, including the new one.

```sh
pnpm --filter <package> i18n:make-po -- <locale>    # create an empty .po
#    → translate <slug>-<locale>.po
pnpm --filter <package> i18n:make-json              # build all locales' dictionaries
```
