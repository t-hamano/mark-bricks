# Translations

How translation files are generated and maintained for MarkBricks.

All files referenced below live in [`languages/`](../languages/).

## File layout

| File                                 | Role                                                                                                                                       | Generated by     |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ | ---------------- |
| `mark-bricks.pot`                    | Translation template (source of truth for which strings exist)                                                                             | `i18n:make-pot`  |
| `mark-bricks-<locale>.po`            | Per-locale translation source (edited by humans)                                                                                           | `i18n:make-po`   |
| `mark-bricks-<locale>.json`          | Jed-format JSON containing both the `mark-bricks` domain (from the `.po`) and the `default` domain (Gutenberg, fetched from WordPress.org) | `i18n:make-json` |
| `mark-bricks-override-<locale>.json` | Optional. Manual overrides for either the `mark-bricks` or `default` domain                                                                | edited by humans |

The `*.json` files are runtime artifacts loaded via `setLocaleData()` from `@wordpress/i18n`.

## Workflow

### 1. Update the POT (after source code changes)

```bash
pnpm i18n:make-pot
```

Scans `src/**` and regenerates `mark-bricks.pot` via `@wp-blocks/make-pot`.
Run this whenever new translatable strings are added or removed.

### 2. Sync the PO (after the POT changes)

```bash
pnpm i18n:make-po          # default: ja
pnpm i18n:make-po pt_BR    # specify a different locale
```

Updates `mark-bricks-<locale>.po` against the POT:

-   Keeps only entries present in the POT.
-   Preserves non-empty `msgstr` and translator comments from the existing `.po`.
-   Drops entries that no longer exist in the POT.

If the `.po` does not exist, it is created from scratch.
The `Last-Translator` / `Language-Team` headers are preserved; `PO-Revision-Date` is overwritten with the current time.

### 3. Translate

Edit the `msgstr` fields in the `.po` directly, or use a tool such as Poedit.

### 4. Build JSON files (before release / after translation updates)

```bash
pnpm i18n:make-json          # default: ja
pnpm i18n:make-json pt_BR    # specify a different locale
```

-   Verifies that the `.po` exists (errors out and points to `i18n:make-po` if missing).
-   Converts the `.po` into the `mark-bricks` domain inside `mark-bricks-<locale>.json` (Jed format; empty `msgstr` entries are skipped).
-   Fetches the matching locale from `translate.wordpress.org` and writes it as the `default` domain inside the same `mark-bricks-<locale>.json`.

## Overriding translations

The `default` domain in `mark-bricks-<locale>.json` is fetched from WordPress.org, but its msgids do not always line up with those of the `@wordpress/*` packages actually bundled into the app. When the msgid drifts (different package version, fork-level changes, etc.), that string falls through untranslated and renders in English. The same can happen if a temporary fix is needed for the `mark-bricks` domain without rebuilding the `.po`. To fill in those gaps, drop a `mark-bricks-override-<locale>.json` next to the main file. It is preserved across re-runs of `i18n:make-json`.

The file follows the same Jed format. Only the msgids you want to override need to be listed; the rest are inherited from the main file. Both the `mark-bricks` and `default` domains can be overridden in the same file.

```json
{
	"locale_data": {
		"mark-bricks": {
			"some app msgid": [ "corrected app translation" ]
		},
		"default": {
			"some gutenberg msgid": [ "corrected gutenberg translation" ]
		}
	}
}
```

The `""` metadata key (`domain`, `plural-forms`, `lang`) is inherited from `mark-bricks-<locale>.json` via message-level merging, so the override file does not need to repeat it.

Sources are merged at the message level in this order (later wins):
`mark-bricks-<locale>.json` → `mark-bricks-override-<locale>.json`.

The override file is optional, never auto-generated, and tracked by hand.

## Adding a new locale

```bash
pnpm i18n:make-po <locale>     # creates an empty .po
# → translate mark-bricks-<locale>.po
pnpm i18n:make-json <locale>   # build the JSON files
```

`<locale>` is a WordPress locale slug (e.g. `ja`, `pt_BR`, `de_DE`, `zh_CN`). See the [WordPress locale list](https://translate.wordpress.org/locale/) for the full set.
